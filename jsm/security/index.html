Security & data handling

Public security and data-handling facts for ReplyMerge for Jira Service Management (Forge cloud app). Contact: support@inflexion.pl.

Runs on Atlassian

The App is a Forge (Cloud) application. End-User Data stays in the customer’s Atlassian Cloud site and Atlassian-hosted Forge storage. There is no vendor-operated database.

  • No Connect modules
  • No AI / model processing of customer content (heuristic match only)
  • Subprocessors: Atlassian only for MVP

See Runs on Atlassian.

No egress of customer data

The App declares no remotes and no permissions.external. Compute runs on Forge; writes go only to Atlassian product APIs under declared scopes. There is no analytics or third-party API that receives in-scope End-User Data.

Security baseline

  • Least-privilege scopes (justified above)
  • No collection/storage of user passwords or long-lived customer API tokens by the App
  • Dependency hygiene before publish
  • Secure handling of attachments during copy (size cap; no vendor persistence)
  • Dry-run default reduces accidental writes

Aligned with Atlassian’s Security requirements for cloud apps.

Vulnerability reporting

Email support@inflexion.pl with subject SECURITY. Do not file public issues for vulnerabilities. Once listed, the vendor follows Atlassian’s Security Bug Fix Policy for Marketplace Apps.
