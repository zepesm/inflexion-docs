Configuration

Product: ReplyMerge for Jira Service Management.

Two layers control dry-run vs live. Both must allow live before auto-merge runs (except the existing live-project guard used for controlled tests).

1. Admin page (per site) — primary control

Jira administration → Apps → Email reply dedupe (Forge UI Kit admin page):

ControlDefaultEffect
Enable auto-merge (live mode)OFFOFF = dry-run (detect/diagnose only). ON = allow merges when the env kill switch also allows live.
Current modederivedShows dry-run vs auto-merge
Effective settingsread-onlyLookback, attachment cap, env kill-switch state, guards (non-secret)

Only Jira administrators can change the toggle. Changes are stored in Forge app storage (storage:app) with who changed it and when.

2. Env kill switch (DEDUPE_DRY_RUN)

Forge environment variables (forge variables set -e <env> …), then redeploy.

ValueEffect
unset / true / anything except false/0Forces dry-run (kill switch ON) — even if the admin toggle is ON
false or 0Allows live only if the admin toggle is also ON

First production deploy: keep DEDUPE_DRY_RUN=true.

forge variables set -e production DEDUPE_DRY_RUN true
# Later, after validation:
# forge variables set -e production DEDUPE_DRY_RUN false
# forge deploy -e production
# Then a Jira admin enables the toggle on the admin page.

Other defaults

  • Lookback window: 14 days
  • Max attachment copy size: 50 MiB
  • Audit property: jsm-email-dedupe.merge
  • Detection property: jsm-email-dedupe.detection

Scopes

Scopes and justifications are listed on the Security & data handling page. Includes read:workflow:jira (close-path pre-check) and storage:app (admin toggle KVS).

Recommended production posture

  1. Deploy with DEDUPE_DRY_RUN=true; leave admin toggle OFF.
  2. Validate detection on a disposable JSM project.
  3. Set DEDUPE_DRY_RUN=false and redeploy only with change control.
  4. Jira admin turns Enable auto-merge ON when ready.
  5. Prefer explicit close transition id/name if the workflow is non-trivial.
  6. Do not use DEDUPE_TEST_CHANNEL_MARKER in production.
